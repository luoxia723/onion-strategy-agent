# 视觉与 Prompt 规范

本文件是 APP 图片 Prompt 的规则 owner。它把当前洋葱投放单图 Prompt 的创意方法迁移到本地 APP 图片流程；本地配置卡、KIE、选择页和不写飞书的边界由 SKILL.md 负责。

## 1. 先建立最小创意链

Prompt 属于 Creative Path，不能只把文案和“学生学习场景”拼在一起。写 Prompt 前先整理：

~~~text
功能事实 → 目标学生 → 具体场景 → 学习阻碍/情绪 → 产品动作 → 可感知变化
~~~

临时文案入口至少完成 Lite 版本：

- 文案锚点：主标题、副标题、CTA（如有）；
- 目标学生：默认学生，除非本轮明确指定其他人群；
- 学生正在经历的具体时刻；
- 他卡在哪里、为什么没有继续；
- 产品在这一帧里具体做了什么；
- 画面让学生感受到什么变化。

产品动作必须来自 产品资料/ 或用户本轮明确提供的事实。例如拍题精学只能使用资料中确认的拍题、分步骤解析、步骤讲解、继续追问等动作；不能把其他功能的规划、诊断、课程或服务动作混进来。

## 2. 单图必须在一帧里讲清楚

单图的目标是让学生在 1—3 秒内看懂：

- 这是自己的学习痛点；
- 洋葱具体提供了什么帮助；
- 画面从“卡住”走向什么可感知变化。

单图 Prompt 至少包含：

1. 具体场景和瞬间，不写泛泛的“学生在学习”；
2. 学生、IP 或工具的动作；
3. 产品动作或产品证据。没有真实 UI 截图时，不编造可识别 APP 页面，可以用纸面步骤、抽象卡片、光效、动作关系或不可读屏幕表达；
4. 图片中的完整中文文案；
5. Logo、IP、字体和风格参考图的用途；
6. 构图、文字层级、色彩、光线、质感和安全区；
7. 禁止项、合规边界和“直接新图”声明。

有 IP 时，正文先确定统一的视觉体系（例如高质量动漫插画、半写实广告合成感或软萌 3D 卡通），再让学生、IP、场景和道具处在同一体系内。IP 第一次出现时写明“某 IP（参考图N）”。文本主导方案可以不用 IP，不为凑角色强行加入。

## 3. Prompt 结构模板

不要求每次使用完全相同的段落顺序，但必须覆盖以下信息：

~~~text
参考图说明：参考图1是……；参考图2是……；参考图3是……。
[渠道语境和画面任务]：信息流/应用商店/学习机的单图语境，以及画面要完成的沟通任务。
[场景与产品动作]：学生处于什么具体时刻，哪里卡住，产品或 IP 做什么，变化如何被看见。
[文案与信息层级]：逐字写出主标题、副标题、CTA；说明位置、字号层级、留白和可读性。
[视觉体系]：人物、道具、构图、颜色、光线、质感和节奏。
[资产约束]：Logo/IP/字体/UI/风格参考图各自的使用边界。
[直接生图和禁止项]：不使用旧广告图、不写 SAME/CHANGE、不编造 UI、不增加未经确认的事实。
~~~

文案必须逐字保留，不能让模型自行改写核心事实、删掉必要补语、添加价格、数字、按钮或效果承诺。

## 4. 尺寸参数不写进 Prompt 正文

比例、像素、出图尺寸、目标尺寸和 KB 上限是配置卡与工具参数：

- Prompt 正文只写“竖版信息流广告海报”“横版应用商店单图”等构图语境；
- render.py 的 size、导出尺寸和压缩目标只从 image-config-result.json 的 placements[] 读取；
- 不要在 Prompt 正文写 720x1280、1080x1920、9:16 或 800KB，避免把制作参数误当成画面内容。

## 5. 参考图顺序和字体规则

完整参考图的默认顺序：

1. Logo；
2. IP；
3. 风格/构图参考（如果本轮选择）；
4. 字体参考；
5. 真实 APP/UI 截图（只有画面确实需要可识别 UI 且用户已上传时）。

实际没有选择某类资产时跳过该类，后续编号顺延。Prompt 中的“参考图N”必须与 reference_images 数组顺序完全一致，路径必须来自本 Skill 的 assets/asset-manifest.json 或本轮用户上传的真实文件。

选择 Logo 时，必须在现有“参考图说明”中原样保留：

> 左上角原样呈现参考图1的完整 Logo，图形、文字、颜色、比例、轮廓及角标均与原图一致，不得重绘、变形、简化或拆分；Logo直接融入画面原有背景，周围延续整体色调，不另加底板、色块、边框或弧形区域，仅调整整体大小和位置。

字体启用时，每张图选一张洋葱字体参考 PNG，并在 Prompt 中写清：

- 参考图N只用于字体气质和排版参考，不复制参考图示例文字；
- 主标题优先遵循参考图N的字形骨架、笔画粗细、转折、外轮廓、描边层级、字面宽窄和排版密度；
- 不要擅自改成另一种书法、手写、卡通、贴纸或渐变字体类型；
- 颜色可以根据当前画面调整，文字必须保持清晰、完整、可读。

这些 PNG 是风格参考，不是真实字体文件；不能承诺像素级复刻。若用户要求严格一致，必须先补充已确认的真实字体文件或确定后处理方案，不能只靠 KIE Prompt 保证。

## 6. 参考图和 UI 门禁

- 用户上传的 Logo、IP、字体或风格图是本轮直接生图参考，不是旧广告图迭代基准；
- 旧广告图、G-ID、同款扩图、换文案保留原风格等需求不进入本 Skill；
- 如果画面有手机、平板、电脑、学习机或其他屏幕，并且屏幕要展示可识别的洋葱 APP/学习 UI，必须先拿到真实截图并将其作为参考图；
- 没有真实截图时，屏幕只能弱化、模糊、偏转、过曝或显示不可读抽象内容，不能写具体页面结构和虚构功能。

## 7. 多套直接生图的差异

同一条文案的多套图片先确定共同视觉 DNA：

- 功能事实、文案、品牌色和字体策略保持一致；
- 场景细节、人物/IP、镜头距离、构图、动作或视觉隐喻至少错开；
- 每套仍然独立生成，不能互相当作已有广告图迭代；
- 不为了“有差异”改变产品事实、文案重点或渠道限制。

## 8. 生成前自检

付费前逐张检查：

- 文案是否逐字一致；
- 功能动作是否来自产品资料；
- 是否在 1—3 秒内看懂痛点、产品动作和变化；
- 参考图标签、顺序、asset_id 和路径是否一致；
- 字体参考是否真的放进 reference_images；
- 是否把尺寸参数留在工具参数而不是 Prompt；
- 是否出现虚构 UI、风险承诺、竞品品牌或旧图继承指令；
- 是否按配置卡的版位、Logo、CTA、套数和 UI 门禁执行。
