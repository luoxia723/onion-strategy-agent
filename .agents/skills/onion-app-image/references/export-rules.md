# 压缩与导出

用户提交选择结果后，运行`scripts/prepare_accepted_deliveries.py`一次处理全部采纳图片；脚本内部调用本地`scripts/image_compress.py`，按每张图已保存版位的精确宽高做cover居中裁切、转为JPEG并压到KB上限，再校验格式、像素、字节数和SHA-256。原图、候选图与采纳交付图分开保存。默认交付`04_交付`目录，不自动生成 ZIP；只有用户明确要求“打包”时才生成。

有精确宽高时不得为了减小体积继续缩小像素；无法同时满足目标尺寸和KB上限时明确失败，不把超限文件写成正式交付。正式流程不调用`generation_prepare_image_delivery`，也不按采纳图片数量向用户重复取得压缩授权。Pillow精确版本由`requirements.txt`锁定。

ZIP固定写入`06_打包/<业务线_功能方向>_APP图片_交付包_<版本>.zip`，相邻保存`..._交付清单.json`，ZIP内部也必须包含不带绝对路径的`交付清单.json`，逐文件记录相对路径、字节数和SHA-256。ZIP只包含`04_交付`中已经校验的采纳JPEG，不包含候选、缓存、临时URL或供应商凭据；打包脚本读取交付规格质检结果，不重复处理图片。

导出前检查：像素、比例、文件格式、色彩、文字可读性、Logo、UI、留白和平台体积上限。平台规格未确认时不声称“已适配”，只输出当前尺寸并标待确认。
