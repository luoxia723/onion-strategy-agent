# 购买动因输入事实要求

## 必需输入

- 已完成的外部需求报告；
- 已完成的内部需求报告；
- 当前正式产品事实：功能、适用人群、使用动作、可支持的变化、明确边界；
- 报告生成时间；
- 用户指定活动日期，或默认从生成当天开始向后约两周的判断范围；
- 本轮业务范围：全部、APP或线索。

当前可以通过文件、数据库、SSH、脚本或已部署 MCP 取得这些事实。Skill 依赖事实内容，不绑定具体工具名。

## 需求报告的使用方式

- 完整读取外部需求报告和内部需求报告，不再加载分散详情文件；
- 外部需求卡是基础候选来源，提供需求主体、具体人群、具体场景、核心问题、当前应对、期待变化、目标时间节点、证据状态、支撑证据数、独立来源语境数和代表证据；
- 内部报告是历史验证输入，提供 APP/线索历史素材数、高表现完整素材数、标准化功能/服务承接和高表现代表素材，不单独创造当前购买动因；
- 只有需求主体、学习/家庭任务、核心问题机制和期待变化兼容时才建立外部/内部对应，不能只按关键词、证据数或功能名匹配；
- 内部高表现关联不把外部需求升级为更强市场结论，也不证明某个需求或承接导致效果；内部报告中的历史承接只作为候选参考，是否可用必须再与独立取得的当前正式产品事实核对；
- 内部报告没有对应结构时，记录“本期未找到达到内部报告纳入标准的对应需求”，不能据此判断需求不存在；
- 不读取或引用任何外部、内部创意报告；创意结构、开头、表现形式和创意案例都不是购买动因输入；
- 外部报告的目标时间节点是本轮默认策略时间节点；用户在购买动因任务中提供更新节点时以最新输入为准；
- 两份报告的外部采集批次和内部完整投放周期可以不同，购买动因还有独立的本轮策略时间范围；三者必须分别如实记录，不能合写成“同周期交叉验证”。

## 输入质量门槛

- 两份需求报告都必须是完整单文件正式报告，并已通过各自确定性校验；
- 内部需求报告必须已经完成跨素材语义合并。仍标记为“关键词候选聚类”“格式验收稿”或“待语义复核”的产物不能作为正式购买动因输入；
- 用户明确只做格式验收时，可以使用验收稿生成带醒目标记的非正式样稿，但不得把候选数量、匹配关系或推荐顺位写成正式业务结论；
- 不使用旧逻辑中当前报告未提供的“内部主需求排名”“需求消耗占比”或“市场需求占比”。

## 时间节点事实

- 使用真实日历日期、学习阶段、节假日或用户指定活动期；
- 不虚构某地区具体开学日、考试日或学校安排；
- 节点事实不足时使用“当前阶段”“接下来约两周”等真实表述；
- 每条候选都要说明为什么这个问题会在当前或接下来约两周出现、变急或值得优先处理。

## 产品事实

- 只能使用已确认功能、使用方式、适用分支和效果边界；
- 产品事实能支持“怎样做”和“先发生什么变化”，不能反向证明需求存在；
- 不能将单一能力扩写成自动规划、保证提分、一次解决或长期结果；
- APP 与线索的真实入口、体验和 CTA 分开使用。

## 缺失处理

- 缺任一需求报告：停止并说明缺哪份正式输入；
- 任一需求报告未达到输入质量门槛：停止正式生成并指出待完成的上游步骤；
- 缺产品事实：停止，不生成解法；
- 时间范围不明但当前日期可得：使用生成当天至后约两周，不追问；
- 某个分支无法形成3个不同核心问题且产品可承接的候选：停止并说明缺口，不交付数量不完整的正式报告。
