# 产品功能方向形成规则

## 一条方向

```text
方向 = 指定功能 × 一个真实需求 × 当前时间阶段 × 一个具体场景问题 × 一个功能承接动作 × 一个可观察变化
```

## 硬门槛

每条方向同时满足：

- 功能为用户指定功能的正式名称；
- 卖点是该功能已确认的具体能力，不是整份产品功能清单；
- 人群与需求报告及产品适用范围一致；
- 适配场景与本轮时间范围和具体学习任务一致；
- 场景包含具体时间/阶段、人物、正在做的学习动作和当场卡点；
- 功能动作能直接接走这个卡点；
- “3 因此带来了哪个场景下的什么‘奇效’”只写使用后当场可观察的变化，不是保证提分或长期结果；
- 与其他方向有实质差异。

## 九列业务展示含义

1. `编号`：从1开始连续编号；
2. `素材方向`：一句能判断主打切口的策略主题，不只是功能名；
3. `功能`：归一后的正式产品功能名称；
4. `卖点`：本条实际使用的一个主要正式卖点；
5. `目标人群`：带学段、身份、行为或当前处境的具体人群；
6. `适配场景`：当前真实场景，如开学第一周第一份新课作业、期中前错题复盘，不写空泛“全阶段”；
7. `1 能解决用户在“具体哪个场景里的哪个问题”`：具体时间/阶段＋人物＋学习动作＋当场卡点＋直接结果；
8. `2 能带来什么不一样的“一听很惊艳”的解法？`：用户如何使用、产品做什么、为什么比旧办法更直接；
9. `3 因此带来了哪个场景下的什么“奇效”？`：同一场景中最先能看到的具体变化。

### 后四列完整度

- `适配场景` 不只写“开学适应期”等节点名，要具体到节点＋任务，例如“9月开学第一周，第一份数学新课作业”；
- `1 能解决……` 要写完整场景链：什么时候、谁、正在做什么、卡在哪里、立即导致什么；
- `2 能带来……` 必须显式写正式功能名和具体产品动作，说明不只是旧办法，而是如何直接处理当前卡点；
- `3 因此带来……` 使用“以前/现在”或等价前后对比，回到同一场景，写可看到的行为或流程变化；
- 三个长字段每列不少于55个汉字/字符。该门槛用来阻止把完整方向缩成一句摘要，不要用同义重复凑字。

## 合并与拆分

以下六项实质相同才合并：目标人群、适配场景、学习任务、核心卡点、主要卖点、功能动作。只换标题措辞不算新方向。

以下任一变化可拆成新方向：不同任务、不同核心问题、不同人群立场、不同时间节点作用、不同主要卖点、不同功能使用动作或不同当场变化。

## 时间规则

- 用户指定活动期优先；否则从生成当天向后约两周；
- 时间节点必须影响用户现在做什么、为什么着急、功能何时介入或想先看到什么；
- 不能只把“开学季、暑假、考试前”填在适配场景而其他列仍是通用话术；
- 不虚构地区学校的具体安排。

## 不使用权重的排序

逐级判断：

1. 当前节点下确实会发生且处理窗口更短的场景优先；
2. 指定功能能直接完成关键动作的场景优先；
3. 多条需求证据支持优先于单条观察；
4. 外部需求和内部 APP 表达同时覆盖优先于只覆盖一侧；
5. 场景、解法和变化更具体者优先；
6. 仍相同时按上游需求编号和候选生成顺序稳定排列。

不打分、不计算权重，也不把顺序解释为投放效果排名。

## 方向依据

每个方向必须记录：

- 外部需求编号；未使用时写“无”；
- 内部需求编号；未使用时写“无”；
- 本方向实际使用的产品事实，必须能在正式资料中定位。

需求编号只用于回溯，不追加到固定9列。外部与内部两侧不能同时为“无”；产品事实不能只写功能名，必须写本条方向使用的具体动作或卖点。

## 数量

- 用户指定数量时，在满足硬门槛和差异要求的候选中输出该数量；
- 未指定时输出所有有效方向，最多6条；
- 有效方向不足时按实际数量输出，不用近义改写凑数；
- 没有有效方向时只说明指定功能与本轮需求无法形成可靠承接。
