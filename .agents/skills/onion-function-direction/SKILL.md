# 产品功能投放策略方向卡

本目录是投放 AI Skills 主仓库中的正式策略 Skill 源码。

## 产物

独立生成一份产品功能投放策略方向卡 Markdown。业务展示固定9列，前5列保持现有名称，后4列使用业务确认的完整名称：

`编号｜素材方向｜功能｜卖点｜目标人群｜适配场景｜1 能解决用户在“具体哪个场景里的哪个问题”｜2 能带来什么不一样的“一听很惊艳”的解法？｜3 因此带来了哪个场景下的什么“奇效”？`

功能保持单独一列，编号、素材方向、功能和卖点都不合并。

方向卡回答“用户指定的这个真实功能，在当前时间下应该承接哪些需求、面向谁、落到什么具体场景”。它不是创意报告，也不直接写图片文案。

## 运行前读取

- [输入事实要求](references/input-requirements.md)
- [方向形成规则](references/direction-rules.md)
- [固定输出模板](references/report-template.md)
- 将用户功能归一或生成方向时，读取当前主仓库的[产品事实与卖点](../../../产品资料/产品事实与卖点.md)。

## 用户输入

用户必须指定本轮要打的产品功能，可以使用业务简称。用户可以补充时间、目标人群、卖点偏好、方向数量或已有方向。

缺少功能时，只询问本轮要打哪个功能，并列出正式产品事实中可选的真实功能；不从需求报告替用户猜功能。功能说法能唯一映射到正式名称时直接归一，不额外确认；无法映射或与产品事实冲突时停止并请用户补充事实。

未指定时间时，从生成当天开始向后看约两周。未指定数量时，输出所有满足硬门槛且有实质差异的方向，默认最多6条；不足不凑。

## 固定流程

1. 取得用户指定功能并映射到正式产品功能，冻结对应功能、卖点、适用人群、使用方式和边界。
2. 冻结外部需求报告、内部需求报告和本轮时间范围。
3. 从两份需求报告中筛出该功能能够真实承接的需求；不能承接的需求明确排除，不强行套功能。
4. 将需求与当前时间节点结合，形成“人群＋阶段＋具体场景问题＋功能动作＋可观察变化”的方向候选。
5. 按硬门槛过滤，并按场景问题、目标人群、卖点或功能动作去重。
6. 用户指定数量时输出指定数量；未指定时最多6条，按规则逐级排序，不使用权重或综合分。
7. 严格生成固定9列业务表格；在表后使用紧凑的“方向依据”将每个方向对应到实际读取的外部需求编号、内部需求编号和本条使用的产品事实。
8. 记录本轮重要但指定功能无法直接承接的需求及拒绝原因；不为了凑数强行套功能。
9. 运行 `scripts/validate_direction.py`，通过后停止在方向卡，不自动进入图片文案或生图。

## 边界

- 外部需求报告、内部需求报告、指定功能、正式产品事实和当前时间节点都是正式上游。
- 不读取外部或内部创意报告。素材创意变化由下游图片文案和图片生成完成。
- 不能因为用户指定功能，就把所有需求都写成该功能可以解决。
- 产品事实不能支持的动作、界面、结果和承诺一律不写。
- 时间节点必须改变场景、问题紧迫性或使用动作，不能只填在“适配场景”一列。
- 每条方向只表达一个清晰切口；多条方向不能只是标题近义改写。
- 方向依据只用于回溯需求和产品事实，不改变固定9列，也不把需求报告整段复制进来。
- 所有修改生成新版本，不覆盖旧文件。

## 完成标准

- 正式功能能在当前产品事实中唯一定位；
- 表内每行都使用该正式功能，编号连续，且九列完整不变；
- 每个方向都有可回溯的需求编号和产品事实；
- 时间节点实际改变场景任务、紧迫性或使用动作；
- 未成案需求没有被伪造成可承接方向；
- 确定性校验器通过。
