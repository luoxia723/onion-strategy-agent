# 内部需求报告模板

```markdown
# 内部需求报告｜YYYY-MM-DD—YYYY-MM-DD

APP统计来源：YYYY-MM-DD—YYYY-MM-DD＋YYYY-MM-DD—YYYY-MM-DD
线索统计来源：YYYY-MM-DD—YYYY-MM-DD
生成时间：YYYY-MM-DD HH:MM（北京时间）
冻结时刻：YYYY-MM-DD HH:MM（北京时间）
承接命名源：产品事实与卖点.md｜版本或哈希
分析媒体：小红书图组＋其他视频
周期完整度：完整
素材分析完整度：完整 / 部分完整
高表现规则：同业务线、同平台、同渠道内，14天消耗大于0的素材取前20%＋单条不少于800元，低于门槛不递补
语义归并：已完成｜映射SHA-256:真实64位摘要
语义归并回执：相对或绝对receipt.json路径

## 1. 报告范围与本期结论

- 只写3至5条帮助理解内部历史需求采用的结论；
- 固定说明高表现只属于完整素材，不证明需求或功能导致效果；
- APP 与线索不做优劣比较。

## 2. 需求一览

### 2.1 APP

| 编号 | 需求名称 | 需求主体 | 具体人群 | 全部素材 | 高表现素材 | 主要功能/服务承接 | 需求详情 |
|---|---|---|---|---:|---:|---|---|
| ID-APP-001 | …… | 学生 / 家长 | …… | N | M | AI拍题精学 | [查看详情](#id-app-001) |

### 2.2 线索

使用相同表头，编号从 ID-LEAD-001 开始。APP 与线索不比较、不合并排名。

报告只收录至少关联2条高表现完整素材的需求。需求一览中的“查看详情”必须跳转到本节对应的显式锚点。

**边界**

这张卡只说明内部历史采用过该需求，以及完整素材主要使用的功能/服务承接。它不证明外部当前需求、效果因果、产品当前可用性或下一期适配。
```

正式报告只通过最终语义映射生成：

```bash
python3 scripts/build_report_from_mapping.py \
  语义运行/normalized_units.jsonl \
  语义运行/final_mapping.json \
  语义运行/receipt.json \
  MCP完整池manifest.json \
  产品资料/产品事实与卖点.md \
  --output 内部需求报告.md

python3 scripts/validate_report.py 内部需求报告.md
```

未完成语义归并的试验稿只能显式使用`--allow-trial-without-semantic-mapping`检查页面格式，不能作为正式报告或下游输入。
