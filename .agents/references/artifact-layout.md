# 统一任务产物目录与命名合同

本合同是三个角色仓库正式产物路径、任务 ID、版本、文件名和交付包的唯一 owner。每个 Skill 只定义自己交付什么，不再另造顶层目录。

## 根目录

所有正式产物按北京时间自然日进入：

```text
工作区/产物/YYYY-MM-DD/<产物大类>/<任务ID>/
├── 任务索引.json
└── v001/
    ├── 00_任务/任务清单.json
    ├── 01_输入/
    ├── 02_过程/
    ├── 03_候选/
    ├── 04_交付/
    ├── 05_质检/
    └── 06_打包/
```

- `工作区/输入`是用户原始输入 owner；任务需要长期留痕的冻结副本或引用写入`01_输入`；
- `.runtime/<任务ID>/`只保存短时下载、模型批次、临时缓存和可重建文件，不是正式交付；
- `04_交付`只放人工可采用的正式文件；候选图、草稿和未采用版本不得混入；
- `05_质检`保存自动检查、人工审核和SHA-256；
- `06_打包`只在需要ZIP时创建交付包和交付清单。

## 任务 ID 与版本

任务 ID 固定为：

```text
<产物代码>-<YYYYMMDD>-<HHMMSS>-<4位十六进制>
```

例如`AIMG-20260828-142530-a3f1`。目录日期与任务 ID 日期都使用北京时间。产物代码与 Skill 的一一对应关系由同目录`artifact-layout.json`维护。

同一业务任务修改时新增`v002`、`v003`，不覆盖`v001`。用户明确要求另一任务或输入身份已经变化时创建新任务 ID。Windows/macOS发行不使用`latest`符号链接；当前版本记录在`任务索引.json`。

## 文件名

正式主文件固定为：

```text
<任务ID>_<产物名称>_<版本>.<扩展名>
```

多份图片或视频在产物名称后增加三位序号，例如：

```text
AIMG-20260828-142530-a3f1_APP图片_方案001_图01_v001.jpg
THM-20260828-150015-b91c_口播主轴混剪_成片001_v002.mp4
```

计划、字幕和质检同样带任务 ID 与版本：

```text
THM-..._混剪计划001_v002.json
THM-..._字幕001_v002.ass
THM-..._质检报告001_v002.json
```

文件名不放空格、斜杠、短时URL、用户隐私或完整文案；可读标题写入任务清单。

## 图片与ZIP

APP图片只把采纳图写入`04_交付`。原图、候选图和服务端处理前文件分别留在`02_过程`或`03_候选`。

默认交付文件夹，不自动生成ZIP；用户要求打包时，ZIP固定写入：

```text
06_打包/<任务ID>_APP图片交付包_<版本>.zip
06_打包/<任务ID>_APP图片交付包_<版本>_交付清单.json
```

ZIP内必须包含`交付清单.json`，逐文件记录相对路径、字节数和SHA-256；不得包含候选图、临时URL、API Key、`.env`、缓存或绝对本地路径。其他产物需要打包时使用同一规则。

## 固定入口

角色 Agent 在执行 Skill 前先运行：

```text
python scripts/artifact_workspace.py create --code <产物代码> --title <任务标题> [--business-line app|lead]
```

修改同一任务使用`new-version`；写完文件后使用`finalize`；需要通用交付包时使用`package`；交付前必须使用`validate`。入口负责目录、命名、版本、清单和哈希，Skill 不手工拼顶层路径。
