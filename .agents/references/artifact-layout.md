# 统一任务产物目录与命名合同

本合同是三个角色仓库正式产物路径、业务可读名称、机器任务 ID、版本、文件名和交付包的唯一 owner。目录和文件首先服务业务人员浏览；机器 ID 只保留在任务索引、哈希和幂等字段中。

## 根目录

所有正式产物按北京时间自然日进入：

```text
工作区/产物/YYYY-MM-DD/<产物大类>/<业务主题_产物名称_HHMMSS>/
├── 任务索引.json
└── v001/
    ├── 00_任务/任务清单.json
    ├── 01_输入/
    ├── 02_过程/
    ├── 03_候选/
    ├── 04_交付/
    ├── 05_质检/
    └── 06_打包/
```

- `工作区/输入`是用户原始输入 owner；任务需要长期留痕的冻结副本或引用写入`01_输入`；
- `.runtime/<任务ID>/`只保存短时下载、模型批次、临时缓存和可重建文件，不是正式交付；
- `04_交付`只放人工可采用的正式文件；候选图、草稿和未采用版本不得混入；
- `05_质检`保存自动检查、人工审核和SHA-256；
- `06_打包`只在需要ZIP时创建交付包和交付清单。

例如：

```text
工作区/产物/2026-08-28/内容文案/APP_开学季拍题_APP视频口播文案_142530/
工作区/产物/2026-08-28/APP图片/APP_拍题精学_APP图片_150210/
工作区/产物/2026-08-28/视频混剪/线索_课程试错_口播主轴混剪_161005/
```

## 业务名称、机器 ID 与版本

目录名称来自当前 Skill 已确认的业务参数，不由使用者填写代码：

| Skill产物 | 业务主题来源 |
|---|---|
| 外部需求报告 | 目标时间节点 |
| 内部需求报告 | 统计周期 |
| 外部/内部创意报告 | 观察范围或报告周期 |
| 购买动因与信息屋 | 策略周期或活动主题 |
| 产品功能方向卡 | 产品功能名称 |
| APP/线索口播文案 | 购买动因名称 |
| APP图片文案/图片 | 功能方向或图片主题 |
| 纯配音混剪 | 确认文案标题或购买动因 |
| 口播主轴混剪 | 母片人物、文案标题或购买动因 |

机器任务 ID 固定为：

```text
<产物代码>-<YYYYMMDD>-<HHMMSS>-<4位十六进制>
```

例如`AIMG-20260828-142530-a3f1`。该值写入`任务索引.json`，不作为业务目录名或主文件名前缀。目录日期与任务 ID 日期都使用北京时间。产物代码与 Skill 的一一对应关系由同目录`artifact-layout.json`维护。

同一业务任务修改时新增`v002`、`v003`，不覆盖`v001`。用户明确要求另一任务或输入身份已经变化时创建新任务 ID。Windows/macOS发行不使用`latest`符号链接；当前版本记录在`任务索引.json`。

## 文件名

正式主文件固定为：

```text
<业务主题>_<产物名称>_<版本>.<扩展名>
```

多份图片或视频在产物名称后增加三位序号，例如：

```text
APP_拍题精学_APP图片_方案001_图01_v001.jpg
线索_课程试错_口播主轴混剪_成片001_v002.mp4
```

计划、字幕和质检同样使用业务主题、产物名称与版本：

```text
线索_课程试错_口播主轴混剪_混剪计划001_v002.json
线索_课程试错_口播主轴混剪_字幕001_v002.ass
线索_课程试错_口播主轴混剪_质检报告001_v002.json
```

文件名不放空格、斜杠、短时URL、用户隐私或完整文案。机器任务 ID、Skill名、输入哈希和完整可读标题保存在任务清单，不挤进业务文件名。

## 图片与ZIP

APP图片只把采纳图写入`04_交付`。原图、候选图和服务端处理前文件分别留在`02_过程`或`03_候选`。

默认交付文件夹，不自动生成ZIP；用户要求打包时，ZIP固定写入：

```text
06_打包/APP_拍题精学_APP图片_交付包_<版本>.zip
06_打包/APP_拍题精学_APP图片_交付包_<版本>_交付清单.json
```

ZIP内必须包含`交付清单.json`，逐文件记录相对路径、字节数和SHA-256；不得包含候选图、临时URL、API Key、`.env`、缓存或绝对本地路径。其他产物需要打包时使用同一规则。

## 固定入口

角色 Agent 在执行 Skill 前先运行：

```text
python scripts/artifact_workspace.py create --code <产物代码> --title <当前Skill的业务主题> [--business-line app|lead]
```

修改同一任务使用`new-version`；写完文件后使用`finalize`；需要通用交付包时使用`package`；交付前必须使用`validate`。入口负责目录、命名、版本、清单和哈希，Skill 不手工拼顶层路径。

## 文档与工作台链接

`validate`会自动检查`04_交付`中Markdown的文内锚点、跨文档相对路径、目标文档锚点和工作台URL结构。也可以对已有报告单独运行：

```text
python scripts/artifact_workspace.py check-links --path <报告或目录>
```

正式报告交付前再运行`--online-workbench`：它会把每个去重工作台链接映射到对应详情API，验证HTTP 200和返回身份与URL完全相等。外部详情规范参数是`content_id`；历史`material_context_id`仅作为兼容参数并产生警告。内部详情必须同时包含`business=app|lead`、`internal_snapshot_id`和`view=analysis`。

工作台链接固定使用`https://toufang-ai.guanghexinzhi.cn/content-dashboard`。相对文档链接必须真实存在且不得越出当前项目；正式报告不能保留`链接`、`真实ID`、`example.com`等模板占位。
