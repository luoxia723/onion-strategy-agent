# 外部需求筛选与归并规则

## 1. 需求单元

每个需求单元使用共同需求卡的六个字段：需求主体、具体人群、具体场景、核心问题、当前应对和期待变化。一个单元只有一个核心问题。

同一证据同时表达孩子学习卡点、家长辅导问题或其他不同机制时，拆成多个需求单元，共享同一证据 ID 和来源语境 ID。

产品功能、广告解法、创意形式、宽主题和分析结论都不是需求。期待变化没有显式证据时，只允许使用问题的最小反向表达。

## 2. 目标时间节点适配

目标时间节点只用于筛选当前批次证据中的需求，不改写证据原意。一个需求至少满足以下一项才进入报告：

- 证据本身的任务或场景属于该节点；
- 该节点会真实改变问题的紧迫性、处理顺序或期待变化；
- 该节点会真实触发证据中已观察到的学习/家庭任务。

只在标题上加“开学”、“期中”、“暑假”而问题不变，不算节点适配。当前批次没有对应证据时可以少于预期数量，不用联想或历史数据补齐。

## 3. 需求主体

- 孩子在做题、听课、复习、记忆或执行学习任务中的卡点是学生需求；
- 家长不会辅导、无法决策、时间精力负担或亲子沟通是家长需求；
- 广告或内容喊给家长，不代表需求主体一定是家长；
- 同一证据包含学生和家长两类真实问题时必须拆分。

## 4. 归并与拆分

以下四项相同或兼容时才合并：

1. 需求主体；
2. 学习或家庭任务；
3. 核心问题机制；
4. 期待变化。

必须拆分：无法开始与开始后无法坚持；没听懂与听懂但不会迁移；不知道先做什么与知道顺序但执行不下去；学生卡点与家长辅导/决策问题；只共享“作业、错题、规划、焦虑、提分”等宽词的表达。

平台、来源、措辞、轻微学段差异、情绪强度和当前旧办法可以不同。关键词、向量和模型检索只用于候选发现；最终必须复核中心证据、同义证据和边界证据。

## 5. 证据与代表

- 内容、评论和广告都能形成需求证据，不设来源权重；
- 数据层保留证据对象、独立来源语境和来源构成，用于守恒、排序和回溯，不展示在业务报告中；
- 只有1条合格内容或评论时，该需求仍进入一览和详情，但默认不进入本期结论；
- 每条需求展示1至3条可点击的原始内容，优先选择需求表达完整、回源可用并覆盖不同来源的内容或评论。

## 6. 详情拆解

每个需求详情必须在完整需求定义之外补充：

- 这个需求具体包括什么：将同一核心问题的可观察具体表现归成1至4类，使用简洁列表展示；
- 这个时间节点下发生了什么：只写证据里出现的任务、紧迫性或处理顺序变化；
- 大家现在怎么处理：将已观察到的做法归成1至4类，使用简洁列表展示。

具体表现和当前做法的成员关系留在数据层，报告只呈现分析后的类别。

## 7. 读取顺序

数据层按来源覆盖、支持成员数和需求编号保持稳定顺序。这只服务阅读，不是市场排名，报告不展示这些排序数字。
