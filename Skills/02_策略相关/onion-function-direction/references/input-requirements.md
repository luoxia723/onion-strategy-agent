# 产品功能方向卡输入事实要求

## 必需输入

- 用户指定的产品功能；
- 当前正式[产品事实与卖点](../../../../产品资料/产品事实与卖点.md)中的功能正式名称、具体动作、卖点、适用人群、使用方式和限制；
- 已完成的外部需求报告；
- 已完成的内部需求报告；
- 用户指定活动期，或默认从生成当天开始向后约两周的时间范围。

当前可以通过文件、数据库、SSH、脚本或已部署 MCP 取得这些事实。Skill 依赖事实内容，不绑定具体工具名。

## 功能归一

- 用户说法与正式功能在产品动作、解决问题和使用方式上唯一对应时，直接采用正式名称；
- 只有名称相似但产品动作不同，不能视为同一功能；
- 正式产品事实没有该功能时，停止并请用户提供功能名称、具体动作、适用场景、事实来源和边界；
- 当前 Skill 不自动把新功能写回正式产品资料，除非用户另行明确要求更新产品事实。

## 需求报告的使用方式

- 完整读取外部需求报告和内部需求报告，不再加载分散详情文件；
- 两份报告共同提供需求主体、具体人群、具体场景、核心问题、当前应对和期待变化；
- 外部报告额外提供目标时间节点、同一需求的具体表现、当前做法、原始内容和边界；数据层证据计数不是方向卡必需的可见字段；
- 内部报告额外提供 APP/线索历史素材数、高表现完整素材数、具体问题表达、当前应对、功能/服务承接和代表高表现素材；
- 方向卡面向 APP 图片链，优先选择 APP 可以真实承接的需求；
- 内部线索表达可以帮助理解问题，但不能把线索服务承诺写成 APP 功能能力；
- 只有需求主体、学习/家庭任务、核心问题机制和期待变化兼容时才建立外部/内部对应；
- 只有需求的具体卡点能被独立取得的当前指定功能动作直接接走时才建立功能关系；内部报告的历史功能/服务承接只作候选参考，相同关键词或相同学科不够。
- 每个成案方向保留所用的外部需求编号和/或内部需求编号；某一侧没有对应时可写“无”，但两侧不能同时为“无”。

## 缺失处理

- 缺指定功能：只询问功能；
- 功能无法映射：停止并请求产品事实；
- 缺任一需求报告或产品事实：停止并说明缺失输入；
- 时间未指定但当前日期可得：使用生成当天至后约两周，不追问；
- 没有任何需求能被指定功能真实承接：输出未成案说明，不生成空洞方向。
