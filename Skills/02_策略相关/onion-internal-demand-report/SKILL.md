# 内部需求报告

## 目的

回答：共同14天内，APP 与线索历史素材分别表达过哪些需求，主要使用什么标准功能或服务承接，覆盖多少素材，其中多少是高表现完整素材。

报告不证明外部真实需求，不根据下一期时间节点提前筛选，不分析创意结构，不展开产品动作、利益、结果、证明、权益或 CTA，不把完整素材表现归因给需求或功能。正式产物是一份可完整读取的 Markdown 单文件。

## 运行前读取

- 使用当前已部署数据工具时读取[HTTP MCP适配](../../references/http-mcp-adapter.md)；
- 冻结数据和控制模型上下文时读取[四份报告上下文与 Token 合同](../../references/report-context-efficiency.md)；
- 写两份需求报告的共同字段时读取[需求卡共同接口](../references/demand-card-contract.md)；
- 确定内部范围和必需事实时读取[取数事实合同](references/data-requirements.md)；
- 拆分、语义归并需求和计数时读取[需求规则](references/demand-rules.md)；
- 执行模型分批归并时读取[语义归并合同](references/semantic-clustering.md)；
- 将历史推广对象对应到标准功能/服务名时读取[承接对象命名合同](references/carrying-naming.md)；
- 写报告时使用[报告模板](references/report-template.md)。

## 用户输入

用户只需明确要求生成、更新或修改正式内部需求报告。不询问目标时间节点。

未指定数据周期时，自动选择最近一个 APP 和线索都完整的共同14天。用户明确要查看某个历史内部周期时可覆盖默认，但仍必须通过共同14天完整性门禁。

正式业务取数优先使用当前 HTTP `onion-intelligence` MCP；只有用户明确提供冻结导出文件时才使用导出输入。不得由本 Skill 直连数据库、SSH或对象存储。当前 MCP 不能提供完整基础素材池时按适配合同停止，不退回高表现素材子集。

## 固定流程

1. 确定共同14天：APP 必须有两张连续、不重叠的周表，线索必须有同起止日期双周表。
2. 使用共享冻结脚本一次取得 APP 与线索完整素材池，冻结范围并核对 APP、线索、渠道、快照和稳定素材总数，记录《产品事实与卖点》的命名源版本。该快照同时供内部创意报告使用；外层对话只接收 manifest，不读取 MCP 每页正文。
3. 建立基础素材池：共同14天表内全部正式素材按稳定素材身份去重，消耗为0也保留。
4. 建立可分析素材池：以已下载内容形成的稳定素材身份作为实际媒体类型；纳入实际为 video 且有当前成功 AI-02 的视频，以及来自小红书、实际为 gallery 且有当前成功 AI-02 的图组。
5. 原表媒体类型只作来源元数据；它与实际素材类型冲突或写成 unknown 时保留质量标记，不单独取消一个真实可用素材的分析资格。无稳定素材身份、未富化、非小红书图片和证据结构缺失不参与归并，只在数据说明中计数。
6. 在完整基础素材池上计算高表现素材：同业务线、同平台、同渠道、同币种内，14天消耗大于0的稳定素材取前20%，且单条不少于800元，低于门槛不递补。同一素材跨渠道复用时只分析一次，但保留各比较组的独立排名与高表现状态。
7. 从本地冻结快照的每条可分析素材拆出一个或多个标准需求单元，重新判断需求主体，保留稳定素材 ID、证据位置和高表现状态。完成快照后不再重复调用内部完整池或把原始素材正文放回外层上下文。
8. 运行 `scripts/prepare_semantic_batches.py`生成无遗漏、无重复的模型批次，再运行`run_semantic_clustering.py init`冻结需求单元、批次清单、摘要和所有批内任务。分批完成不等于语义归并完成。
9. 使用`run_semantic_clustering.py`完成全部批内模型归并和跨批模型归并。模型可以修正需求主体，但不能改变业务线或漏掉需求单元；每个任务通过结构与守恒校验后才写入断点。外部付费模型调用必须取得当前任务明确授权；没有授权时只允许`init`、`status`、`next`和人工`accept`，不得假装已经运行。
10. 只有运行状态为`complete`、`receipt.json`为`passed`、`final_mapping.json`摘要与回执一致，并且`validate_semantic_mapping.py normalized_units.jsonl final_mapping.json`通过，才允许进入报告生成。缺少任一项时停止并报告`internal_semantic_mapping_incomplete`；禁止回退到关键词、粗分桶或旧候选卡。
11. 在每个最终需求簇内按稳定素材 ID 去重，计算全部素材数和高表现素材数。
12. 为每条成员素材确定一个主要功能/服务承接，使用正式《产品事实与卖点》中的标准名。无法唯一映射的状态只保留在数据层和素材回源中，不写入报告的“主要功能/服务承接”。不展开产品动作、利益、结果、证明、权益或 CTA。
13. 在每个最终需求簇内，将同一核心问题的具体问题表达归成1至4类，并将素材中明确出现的当前应对归成1至4类。每类都按稳定素材 ID 去重，计算全部素材和高表现素材数。
14. 报告只收录至少关联2条高表现完整素材的需求。低于门槛的需求仍参与全量分析和语义归并，但不进入报告一览或详情。
15. 每个进入报告的需求只选高表现完整素材作为代表：共有2至5条时全部展示，超过5条时选5条。优先覆盖不同的已识别功能/服务承接，再选需求表达清楚且不近义重复的素材。报告只列标题和公司云工作台绝对链接，不写“代表原因”。
16. 使用`scripts/build_report_from_mapping.py`从`normalized_units.jsonl`、`final_mapping.json`、语义回执、MCP完整池manifest和正式产品事实生成单文件报告。不得让模型或外层程序绕开最终映射重新分组。
17. 运行`scripts/validate_report.py <报告>`。正式校验器会回读语义回执并核对映射摘要；只有通过后才能交给购买动因或功能方向卡。明确标注的试验稿只能使用`--allow-trial-without-semantic-mapping`做格式检查，且不能进入下游。

## 完整性与边界

- APP 任一周缺失、两周不连续、线索双周缺失、日期不一致、分页未完成或总数无法守恒时停止正式报告；
- 语义运行停在批内、跨批、映射或校验任一中间状态时停止正式报告；分批文件、关键词候选和格式校验都不能替代完成回执；
- 范围和总数完整，但个别素材不可分析时可继续，并公开准确数量和原因；
- 没有任何可分析素材时不生成可供下游消费的正式报告；
- 同一素材可以支持多个真实需求，不同需求的素材数不得求和；
- 功能/服务承接是历史素材搭配，不代表该功能导致表现或当前仍适合复用；
- 未进入高表现素材池不等于表现差、需求无效或以后不会跑出。

## 修改已有报告

只改表达时继承原周期和素材成员；改需求归并、功能/服务承接或代表素材时重算受影响需求；更新数据时重新冻结范围。所有修改生成新版本，不覆盖旧报告。

## 完成标准

- 报告不要求用户输入目标时间节点，只记录内部数据周期；
- APP 两周与线索双周完全对齐；
- 基础素材池包含全部稳定素材，不设消耗准入门槛；
- 每条需求都使用共同需求定义，并计算全部素材数、高表现素材数和功能/服务承接；
- 报告头记录最终语义映射SHA-256和可回读的语义运行回执，二者必须一致；
- 报告中每个需求至少关联2条高表现完整素材，一览与详情一一对应；
- 需求一览的“查看详情”能跳转到同一文件内的对应需求卡；
- 一览不重复具体场景、核心问题和期待变化；详情额外展示具体问题表达和当前应对统计；
- 主要功能/服务承接只展示正式标准名，不显示未归一状态；
- 每张卡展示 `min(该需求高表现素材数, 5)` 条可回源高表现素材，不写代表原因；
- 报告是单个、紧凑、可完整读取的 Markdown；
- 报告和确定性校验器通过后才交给购买动因或功能方向卡。
