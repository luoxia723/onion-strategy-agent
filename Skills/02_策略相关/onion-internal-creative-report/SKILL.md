# 内部视频创意报告

## 目的

回答：本期洋葱内部完整视频采用了哪些可迁移创意关系，APP与线索怎样呈现这些关系，以及相关完整素材处于什么真实表现背景。

正式产物是一份单文件 Markdown。完整案例与原始表现留在数据层；报告只展示可消费结构、2至3条标准化代表案例和内部采用观察。

## 运行前读取

- 使用当前已部署数据工具时读取[HTTP MCP适配](../../references/http-mcp-adapter.md)；
- 冻结数据和控制模型上下文时读取[四份报告上下文与 Token 合同](../../references/report-context-efficiency.md)；
- 写两份创意报告的公共部分时读取[创意结构共同接口](../references/creative-structure-contract.md)；
- 冻结周期、核对案例和表现事实时读取[取数与完整案例要求](references/data-requirements.md)；
- 提取、合并和拆分结构时读取[案例与结构归并规则](references/creative-rules.md)；
- 写报告时使用[报告模板](references/report-template.md)。

## 用户输入

用户只需明确要求生成、更新或修改内部视频创意报告。用户可以指定统计周期、业务线、渠道或已有报告；未指定周期时自动采用最近一个完整结束且已有反馈数据的共同周期。

默认同时纳入 APP 与线索；用户明确只要其中一个时，仅生成对应范围并说明另一业务线未纳入。APP与线索无法对齐周期时停止，不拼接不同周期。

正式业务取数使用统一 HTTP `onion-agent` OAuth MCP；只有用户明确提供冻结导出文件时才使用导出输入。不得由本 Skill 直连数据库、SSH或对象存储。当前 MCP 不能提供全部完整视频和未入池对照时按适配合同停止。

## 固定流程

1. 确定同一内部统计周期、业务线、渠道、视频边界、生成时间和冻结时刻，生成版本内报告 ID。
2. 复用与内部需求报告相同的内部完整素材池冻结快照；只有快照不存在或范围、版本不同时才重新完整分页。快照包含基础素材池、当前富化、回源链接、稳定素材14天汇总消耗、比较组和高表现素材池标记；以稳定素材的实际媒体类型筛出视频，核对稳定案例总数、业务线/渠道构成和缺失。外层对话只接收 manifest，不读取 MCP 页面正文；原表图片/视频标签冲突只作质量标记，不覆盖真实素材类型。
3. 为每个案例取得开头、推进、转折、产品或证据怎样承接、结尾怎样行动及可定位画面或转写证据。
4. 按共同六维语义提取结构观察；关键词、向量或模型只发现候选。每个隔离批次只输出`internal_material_id`绑定的六维观察；表现字段由程序保留，不进入结构语义。
5. 跨批归并只读取六维观察、中心案例、边界案例和必要业务线元数据，不再次插入完整素材池。使用硬合并/拆分规则复核中心案例和边界案例；APP、线索、渠道和表现不能改变结构语义。
6. 至少2条独立完整案例支持同一关系时进入结构一览与详情；只有1条时进入“单案例信号”。
7. 按去重完整案例数从高到低排列，案例数相同时使用稳定语义键，再从`IC-001`起连续编号；高表现关联状态和消耗不参与编号。填写共同定义表、适合/不能怎样使用、内部采用和2至3条结构代表案例。
8. 在同业务线、同平台、同渠道内计算结构全部素材、高表现素材、未入池素材、结构高表现占比和组内基础占比，形成高表现素材—创意结构关联状态。
9. 每个结构展示2至5条高表现创意代表素材；超过5条时先覆盖比较组，再优先选择各组内14天汇总消耗靠前素材。另选1至2条同结构对照素材，不称为反例。
10. 同周期有已验收逐素材结构映射时，先按快照逐记录哈希复用未变化记录，只把新增、变更和删除影响送入隔离模型任务；最终仍对全部结构摘要、中心和边界案例做全局复核。模型任务不继承当前长对话，也不重复插入完整素材池。按共同五段骨架生成报告，运行 `scripts/validate_report.py <报告>`；存在硬错误时不得称为完成。

## 完整性与边界

- 只分析可回源画面、画面顺序、可见动作、屏幕文字和转写文案；
- 真人/AI、UI真实性、语调、音色、声音感染力、消耗和转化都不能进入结构指纹；
- 真人口播、花字、快剪、产品录屏等表面形式不能单独成为创意结构；
- 同一案例可以支持多个可定位结构，但在同一结构内只计一次；
- 表现只属于完整素材，不证明结构、开头、文案或产品部件造成效果；
- APP、线索和不同结果口径的渠道分别保留，不合成结构效果分；
- 使用仓库已确认的高表现素材池规则，不另设创意专属门槛，也不把未入池素材写成差；
- 周期无法冻结、分页版本变化、总数无法守恒或稳定素材身份缺失时停止，不用局部样本冒充完整报告；个别无身份效果记录可保留在基础统计并从视频分析池排除，不把整个周期误判为不完整；
- 报告不生成口播、前贴、分镜、混剪或三个下游执行器。

## 下游 interface

第2、3部分必须符合共同接口。下游先读取结构一览筛候选，再读取候选卡和代表案例；记录“报告文件＋IC短编号＋实际参考素材”。内部表现背景只帮助理解采用事实，不能成为新广告承诺。

没有适配结构时允许下游原创。单案例信号默认不参与筛选，只有用户明确选择时才能作为探索参考。

## 修改已有报告

只改表达时继承原范围、报告 ID 版本和结构成员；改归并时重算受影响结构及采用背景；更新数据时重新冻结范围并生成新报告版本。不得覆盖旧文件。

## 完成标准

- 周期、稳定案例数和业务线/渠道构成守恒；
- 所有可复用结构至少有2条独立案例；
- 共同定义表、IC连续编号、内部采用和代表案例格式通过校验；
- 创意结构一览中的每个`查看详情`都跳转到唯一IC详情锚点；
- APP/线索差异不改变公共结构语义；
- 完整素材表现没有被写成结构或部件因果；
- 高表现代表素材来自结构成员与高表现素材池交集，并显示比较组、14天消耗和组内排名；
- 同结构对照素材来自同一比较组内未入池且消耗靠前的完整素材；
- 结构关系能够被口播文案和 AI 前贴按共同 interface 筛选。
